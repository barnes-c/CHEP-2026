\section{Current Infrastructure Landscape and Challenges}\label{infra}

CERN operates its own cloud infrastructure based on OpenStack~\cite{dupuis2025,savchenko2024preparing}. Beyond OpenStack, several in-house services manage the machines state, trust, and network configuration~\cite{martelli2018}. Foreman serves as the central External Node Classification (ENC) system for Puppet, maintaining hostgroup assignments, environments, and metadata consumed during catalog compilation.

Production systems are typically provisioned through an internal tool that encapsulates the above mentioned services to create resources. Once these are created a cloud-init script runs to perform the bootstrapping for Puppet which will handle the lifecycle management of a machine. Once the Puppet agent performs its first catalog request the host transitions into ongoing CM.

eThe pain points within this landscape do not originate from deficiencies within individual tools or services, but from the interfaces between them. State is distributed across Foreman, OpenStack, alert management, state management, and a network database, with parts duplicated or derived independently. When changes propagate through different tools, inconsistencies arise to the point where manual correction is needed. Key limitations include: overlapping state representations across systems with delayed convergence asynchronous change propagation with weak end-to-end guarantees; manual steps remaining in provisioning for registration, hardware tracking, and exceptional workflows; and limited end-to-end observability with slow feedback loops. The internal tool, which is commonly used to deploy infrastructure, itself follows a fire-and-forget model, performing no pre-flight checks on permissions or quota and failing silently on errors.

The absence of a single declarative model encompassing all the artifacts (virtual resources, service-level configuration, and supporting registrations) limits end-to-end automation and makes convergence dependent on cross-system coordination. These constraints motivate the exploration of a Terraform/OpenTofu-based framework to reduce boundary drift, improve idempotency across layers, and increase traceability of change.
