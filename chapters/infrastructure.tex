\section{Current Infrastructure Landscape and Challenges}\label{infra}

CERN has its own cloud based on OpenStack~\cite{dupuis2025,savchenko2024preparing}. In this cloud several in-house services are running which manage the state of servers, their trust (secrets/certificates), and network configuration~\cite{martelli2018}. Foreman is used to assign the servers hostgroups and environments. Puppet then uses these to apply specific configurations for each of them.

Currently servers are mostly provisioned through the OpenStack web interface or through an internal tool that wraps those services needed into a Command-Line Interface (CLI) for creating servers. It injects a cloud-init script when a server boots, configuring Puppet, which then takes over lifecycle management of the server. From this point on the host is part of the central CM.

This is not the first time Terraform is used in the IT department at CERN. The Batch Service has evaluated it for bootstrapping Kubernetes clusters, storing manifests in GitLab and applying them from CI/CD, after running into the same home-grown tooling that stitches OpenStack, Foreman, and Puppet together~\cite{alvarez2020batch}. We build on this pattern, but apply it to a more general audience instead of a single service.

One of the first problems we need to solve is how the different tools interact between each other. State lives in Foreman, in OpenStack, in alert management, in state management, and in a network database, and parts of it are duplicated or derived independently in more than one place. A change that propagates through several of these systems can leave them disagreeing, and someone has to go and fix it by hand. Four limitations stand out. State representations overlap across systems and converge late. Change propagates asynchronously with weak end-to-end guarantees. And end-to-end observability is limited, so feedback loops are slow. The CLI that most people use to deploy infrastructure is itself fire-and-forget. It runs no pre-flight checks on permissions or quota, and it fails silently.

What is missing is a single approach covering all of the artifacts involved. Without this approach an end-to-end automation stops short and convergence depends on coordinating across systems by hand. That is the gap a Terraform/OpenTofu-based framework is meant to close, by reducing boundary drift, making the layers idempotent, and making change traceable.
