\section{Introduction}
\label{intro}

CERN has a large computing infrastructure. Since 2012 a configuration management (CM) system around Puppet and OpenStack, together with a number of in-house services has been built up, to manage its computing services~\cite{bellinfra2012}.
All of these tools are adequate for the job, but are operating in isolation from each other. This is visible in the amount of effort the configuration management team has to put into tracing, reproduction, and maintenance.

Procedures for managing servers already exist. The main pain point is keeping the service documentation in sync with the infrastructure, especially in an environment with frequent personnel rotation. When the person who sets a service up is no longer around, recovering or reconfiguring it is slow. Because of the nature of IaC tools, the written code (the desired state of the infrastructure) is the documentation. Another pain point is that tools like Puppet only manage the configuration of a server~\cite{loope2011managing}. If the server underneath the CM becomes degraded or even down the CM cannot recover by itself.

In the past few years IaC has become a go-to model for consolidating how infrastructure is developed, deployed, and automated~\cite{morris2025infrastructure}. Tools like Terraform, and its community-driven fork, OpenTofu, are the most common ones and are a good basis for unifying provisioning and configuration in a reproducible and scalable way.

This work aims to design and implement an IaC-based framework that integrates with the existing infrastructure management ecosystem and that gives operators a single automated and traceable way to manage resources spread across cloud regions and data centres. 
If the integration works, the payoff is less operational complexity and maintenance effort, better automation and reproducibility, and a far easier path through Business Continuity / Disaster Recovery (BC/DR) and cross-environment replication. We see it as a first step towards a more unified infrastructure management strategy at CERN.
